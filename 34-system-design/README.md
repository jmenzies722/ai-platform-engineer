# 34 — System Design

System design converts uncertain requirements into explicit boundaries, data flows, invariants, and tradeoffs that can be tested and operated.

## What you will learn

- Clarify requirements and estimate load.
- Choose interfaces, data models, and consistency boundaries.
- Design for failure, evolution, and evidence.

## Lessons

1. [Requirements, load, and boundaries](01-requirements-load-and-boundaries.md)
2. [Data, consistency, and reliability](02-data-consistency-and-reliability.md)
3. [Evolution and design review](03-evolution-and-design-review.md)

## Practice

Produce a one-page design for a model inference API, including assumptions, capacity math, failure handling, security, migration, and open questions.

## Ready to continue

You can defend a design from requirements through operations and identify which assumptions need measurement.
