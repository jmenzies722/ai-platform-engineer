# Architecture Practice

This directory is for reusable architecture exercises, diagrams, decision records, capacity models, and design reviews that span modules.

A useful architecture artifact states:

- users, workloads, constraints, goals, and non-goals;
- quality attributes with measurable thresholds;
- data and control flows, ownership, trust boundaries, and failure domains;
- state, consistency, capacity, cost, security, and operability;
- decisions, alternatives, assumptions, and revisit triggers;
- migration, rollback, and verification strategy.

Diagrams supplement prose; they do not replace contracts or reasoning. Prefer several diagrams with explicit viewpoints over one unreadable “everything” diagram. Validate a design through a build, measurement, or failure experiment whenever possible.
