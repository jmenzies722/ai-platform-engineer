# Interview Practice

Use [INTERVIEW-MAP.md](../INTERVIEW-MAP.md) to connect domains to interview themes. The [module-mapped question bank](module-question-bank.md) provides calibrated mechanism, debugging, design, follow-up, and scoring prompts across modules 00–35.

Practice from evidence:

1. Clarify requirements and state assumptions.
2. Build a model before naming products.
3. Trace normal operation and critical state.
4. Identify bottlenecks, trust boundaries, and failure domains.
5. Quantify load, latency, availability, recovery, and cost.
6. Respond to changed constraints.
7. Record the weakest follow-up and produce a lab or design that closes it.

Do not memorize a canonical diagram. Strong answers expose tradeoffs, uncertainty, and verification paths.

## Session formats

- **Mechanism, 25 minutes:** one module question, one practical prompt, one changed constraint.
- **Debugging, 45 minutes:** begin with symptoms from an [incident drill](../incidents/README.md); reveal evidence only when requested.
- **Design, 60 minutes:** select a project or architecture brief and require estimates, failure handling, security, operations, and evolution.
- **Staff, 60 minutes:** combine a technical design with stakeholder disagreement, sequencing, risk, and an outcome review.

End every session with the scoring record in the question bank and one concrete evidence task. Repeating the same answer is not remediation.
