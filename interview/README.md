# Interview Practice

Use [INTERVIEW-MAP.md](../INTERVIEW-MAP.md) to connect domains to interview themes. This directory is for question sets, timed designs, debugging drills, and retrospectives.

Practice from evidence:

1. Clarify requirements and state assumptions.
2. Build a model before naming products.
3. Trace normal operation and critical state.
4. Identify bottlenecks, trust boundaries, and failure domains.
5. Quantify load, latency, availability, recovery, and cost.
6. Respond to changed constraints.
7. Record the weakest follow-up and produce a lab or design that closes it.

Do not memorize a canonical diagram. Strong answers expose tradeoffs, uncertainty, and verification paths.
