# Glossary

Definitions are intentionally concise. **First lesson** points to the earliest curriculum treatment; **deeper source** points to an authoritative specification, documentation set, or primary work.

| Term | Concise definition | First lesson | Deeper source |
|---|---|---|---|
| Abstraction | A contract that hides selected implementation details so users can reason at a different level; hidden details still reappear through performance, limits, and failure. | [Why Software Exists](00-history/02-why-software-exists.md) | [Abstraction and Specification in Program Development — MIT](https://pmg.csail.mit.edu/papers/abstraction-and-specification.pdf) |
| Agent | A software loop that observes state, selects actions, uses tools, and evaluates results toward a goal under policy and resource constraints. | [Agentic Engineering](00-history/20-agentic-engineering.md) | [AI Risk Management Framework — NIST](https://www.nist.gov/itl/ai-risk-management-framework) |
| Assembly language | A symbolic representation of machine instructions and addresses, translated by an assembler into machine code. | [Machine Code to Assembly to High-Level Languages](00-history/03-machine-code-assembly-high-level-languages.md) | [System V ABI](https://gitlab.com/x86-psABIs/x86-64-ABI) |
| Compiler | A program that transforms a source representation into another representation, often machine code or bytecode, while preserving defined semantics. | [Machine Code to Assembly to High-Level Languages](00-history/03-machine-code-assembly-high-level-languages.md) | [LLVM documentation](https://llvm.org/docs/) |
| Container | An isolated process or process group packaged with a filesystem and configuration; on Linux it relies on kernel mechanisms such as namespaces and cgroups rather than a separate guest kernel. | [Containers](00-history/12-containers.md) | [Open Container Initiative specifications](https://opencontainers.org/) |
| Control plane | The components that accept intent, store desired state, make decisions, and reconcile or configure a data plane. | [Kubernetes](00-history/13-kubernetes.md) | [Kubernetes control plane components](https://kubernetes.io/docs/concepts/overview/components/) |
| CPU | The processor that fetches, decodes, and executes instructions while interacting with registers, caches, memory, and devices. | [Origins of Computing](00-history/01-origins-of-computing.md) | [Intel Software Developer Manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) |
| Database | A managed system for storing and retrieving data while enforcing selected guarantees around structure, concurrency, integrity, and durability. | [Databases](00-history/08-databases.md) | [PostgreSQL documentation](https://www.postgresql.org/docs/) |
| Distributed system | A system whose components communicate over a network and must make progress despite independent failure, delay, and incomplete knowledge. | [Distributed Systems](00-history/09-distributed-systems.md) | [Time, Clocks, and the Ordering of Events — Lamport](https://www.microsoft.com/en-us/research/publication/time-clocks-ordering-events-distributed-system/) |
| Interpreter | A program that executes a representation of another program, often after parsing or compiling it into an intermediate form. Compilation and interpretation can coexist in one runtime. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [Python language reference](https://docs.python.org/3/reference/) |
| Kernel | The privileged core of an operating system that manages processes, memory, devices, filesystems, protection, and system calls. | [Evolution of Operating Systems](00-history/05-evolution-of-operating-systems.md) | [Linux kernel documentation](https://docs.kernel.org/) |
| Kubernetes | An extensible API-driven system that reconciles declared workload and infrastructure state across a cluster. | [Kubernetes](00-history/13-kubernetes.md) | [Kubernetes documentation](https://kubernetes.io/docs/) |
| Large language model (LLM) | A parameterized model trained to estimate token-sequence distributions at large scale, then often adapted for instruction following and tool use. | [Transformers and LLMs](00-history/17-transformers-and-llms.md) | [Attention Is All You Need](https://arxiv.org/abs/1706.03762) |
| Machine code | Binary-encoded instructions executed according to a processor instruction-set architecture. | [Machine Code to Assembly to High-Level Languages](00-history/03-machine-code-assembly-high-level-languages.md) | [RISC-V ISA specifications](https://riscv.org/technical/specifications/) |
| Observability | The ability to investigate a system’s internal behavior from the evidence it emits, supported by telemetry design and debuggable architecture. | [SRE and Observability](00-history/14-sre-and-observability.md) | [OpenTelemetry documentation](https://opentelemetry.io/docs/) |
| Operating system | Software that multiplexes hardware resources, enforces protection boundaries, and offers abstractions such as processes, files, virtual memory, and sockets. | [Evolution of Operating Systems](00-history/05-evolution-of-operating-systems.md) | [The Linux Programming Interface](https://man7.org/tlpi/) |
| Process | An operating-system execution context with an address space, resources, security identity, and one or more threads. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [Linux proc(5)](https://man7.org/linux/man-pages/man5/proc.5.html) |
| Runtime | The services and machinery that support a program while it executes, potentially including interpretation, compilation, memory management, scheduling, and standard libraries. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [Python/C API introduction](https://docs.python.org/3/c-api/intro.html) |
| Service-level indicator (SLI) | A quantitative measure of service behavior relevant to a user, such as the proportion of valid requests served successfully within a latency threshold. | [SRE and Observability](00-history/14-sre-and-observability.md) | [Google SRE: Service Level Objectives](https://sre.google/workbook/implementing-slos/) |
| Service-level objective (SLO) | A target for an SLI over a defined window, used to make reliability expectations and tradeoffs explicit. | [SRE and Observability](00-history/14-sre-and-observability.md) | [Google SRE books](https://sre.google/books/) |
| System call | A controlled transition through which a user-space process requests a kernel service. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [Linux syscall(2)](https://man7.org/linux/man-pages/man2/syscall.2.html) |
| Thread | A schedulable execution stream within a process; threads usually share the process address space and resources. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [POSIX pthreads](https://pubs.opengroup.org/onlinepubs/9699919799/basedefs/pthread.h.html) |
| Transformer | A neural-network architecture centered on attention and position-wise transformations, enabling highly parallel sequence training. | [Transformers and LLMs](00-history/17-transformers-and-llms.md) | [Attention Is All You Need](https://arxiv.org/abs/1706.03762) |
| Virtualization | Creating a logical computing environment whose resource interface is mediated and isolated from underlying physical resources. | [Virtualization and Cloud](00-history/10-virtualization-and-cloud.md) | [AWS Nitro System](https://aws.amazon.com/ec2/nitro/) |
| Virtual memory | An address-space abstraction mapped by the OS and hardware to physical memory, files, shared pages, or no current backing. | [How Software Actually Executes](01-software-foundations/01-how-software-actually-executes.md) | [Linux memory management documentation](https://docs.kernel.org/mm/) |
